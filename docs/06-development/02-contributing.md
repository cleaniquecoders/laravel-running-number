# Contributing

Thank you for considering contributing to Laravel Running Number! This guide will help you get started.

## Ways to Contribute

- **Report Bugs**: Submit issues on GitHub
- **Suggest Features**: Propose new features or improvements
- **Submit Pull Requests**: Contribute code improvements
- **Improve Documentation**: Help improve or translate documentation
- **Share Examples**: Share real-world usage examples

## Reporting Bugs

When reporting bugs, please include:

1. Laravel version
2. PHP version
3. Package version
4. Steps to reproduce
5. Expected behavior
6. Actual behavior
7. Stack trace (if applicable)

## Submitting Pull Requests

### Process

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/my-feature`
3. Make your changes
4. Write/update tests
5. Ensure tests pass: `composer test`
6. Run code styling: `composer format`
7. Run static analysis: `composer analyse`
8. Commit with clear messages
9. Push to your fork
10. Submit a pull request

### Code Standards

- Follow PSR-12 coding standards
- Write tests for new features
- Update documentation
- Keep backward compatibility when possible

### Testing

```bash
# Run tests
composer test

# Run with coverage
composer test-coverage

# Run static analysis
composer analyse

# Fix code style
composer format
```

## Development Guidelines

1. **Write Tests**: All new features must include tests
2. **Documentation**: Update docs for any user-facing changes
3. **Backward Compatibility**: Avoid breaking changes
4. **Code Quality**: Maintain high code quality standards
5. **Commit Messages**: Write clear, descriptive commit messages
